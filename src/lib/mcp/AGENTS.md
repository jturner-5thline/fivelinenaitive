- MCP Deal Calendar writes use the invoker `mcp_write_deal_calendar_item` RPC (deal-scoped lock, per-deal unique idempotency_key, deal_activity row in the same transaction) — why: keep Deal Calendar RLS, avoid retry duplicates and attribute every change to MCP.
- MCP relationship tools (engagements, outside deals, intro paths, company owners) write caller-scoped and log to own-user `mcp_lender_write_log` (also idempotency keys) — why: no columns may be added to existing tables.
- `merge_lenders` moves the Nov-2026 lender tables via definer `private.merge_lender_new_tables`, callable only inside the `app.lender_merge_pair` merge context; the new-table prepare triggers allow lender_id changes only in that context — why: those tables have no caller UPDATE policies and lock lender_id.
- Lender stage history lives in append-only `deal_lender_stage_events`, filled only by an AFTER UPDATE OF stage insert trigger on deal_lenders; performance scores are written through invoker `upsert_lender_performance` (score + history row in one transaction) — why: additive-only rules allow no other writes to existing tables.
